# Откат

Перед откатом с версии, содержащей `hook_queue`, проверьте `foundation_trace_health`. При `hook_queue_pending > 0` сначала обработайте очередь через `foundation_trace_reconcile` и сохраните согласованную копию координатора и приёмника. Наличие `hook_queue_quarantined > 0` требует разбора конфликта; удаление строк ради разрешения отката запрещено. Старый обработчик не умеет продолжать эту очередь, поэтому возврат старого пакета при непустой очереди без отдельного плана переноса не допускается. Дополнительная таблица не удаляется при откате.

1. Запретить новые выдачи lease и новые записи через bridge.
2. Дождаться завершения либо классифицировать неизвестный исход каждой активной операции.
3. Выгрузить runtime outbox и сверить Dolt commit refs с предметными объектами.
4. Отключить `hermes-foundation-bridge` штатной командой Hermes.
5. Удалить квитанцию `runtime/release-verification.json`, чтобы новый процесс не доверял отозванной поставке.
6. Вернуть предыдущую точную папку пакета только из проверенной подписанной копии и повторно вызвать её проверку выпуска; при её отсутствии оставить bridge отключённым.
7. Не удалять Dolt, SQLite и артефакты. Восстановление данных проверять в пустом альтернативном корне; прежние состояния не считать автоматически принятыми.
8. Повторить migrations dry-run, характерные пробы и сверку. Производственную активацию не разрешать без подписанной поставки, лицензии и полного G0–G8.

`native-runtime.json` и файл пароля Neo4j не входят в подписанный архив. При возврате к прежнему выпуску сохраните их как конфигурацию экземпляра и проверьте совместимость прежнего выпуска с местными службами до включения записи. Старые контейнерные настройки не заменяют проверку адресов, прав на секрет и независимое обратное чтение AgentMemory и Neo4j. Не удаляйте данные служб ради отката кода.

При откате с индекса v2 на v1 не скрывайте активные записи v2: если их число ненулевое, возврат версии пакета без отдельной миграции данных запрещён. Коллекция и манифест v1 сохраняются для обратного чтения, но не объединяются с v2 автоматически.

Для отката с SQL-авторитета 0.9.0 сначала остановите сервер Dolt. Старый встроенный CLI-маршрут должен пройти отдельную проверку на копии данных; при неизвестном исходе коммита или наличии неучтённого писателя старый пакет не включается. Файлы `privileges.db`, `branch_control.db` и секреты сохраняются для восстановления и расследования.

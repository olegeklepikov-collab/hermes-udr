# Действующий авторитет Dolt SQL

Подписанный пакет 0.9.0 переключает предметные записи четырёх баз на ограниченный Dolt SQL Server только при наличии точного `foundation/dolt/sql-authority.json`. Без него встроенный CLI остаётся пригодным для локального начального развёртывания и испытаний, но `foundation_bridge_health` возвращает запрет `dolt_sql_authority_missing`.

Скрипт `scripts/provision_dolt_sql.py` сначала выполняется без `--apply`: он проверяет четыре новые базы и отсутствие прежних или частичных файлов полномочий. При `--apply` в остановленном SQL-сервере он создаёт новый закрытый ключ администратора вне основания и отдельный ключ писателя внутри `foundation/dolt/.secrets`, оба с правами `0600`. Значения передаются локальной команде Dolt через стандартный ввод, не через аргументы процесса, квитанции или журнал. Пароль исходного `root` устанавливается до запуска сервера.

Сервер привязывается к `127.0.0.1:3317`. Точный `server.yaml` ограничивает число соединений и каталог экспорта файлов; удалённый API, MCP и опубликованные порты не включаются. Писатель `foundation_writer` получает только SELECT/INSERT/UPDATE/DELETE/EXECUTE в `kw_core`, `kw_context`, `kw_quant`, `kw_registry` и read/write для ветви `main`. Глобальная запись `%/%/%/%` удаляется. Административная учётная запись хранится отдельно; мост не применяет её. `DOLT_COMMIT('-am', message)` выполняется последним действием SQL-транзакции, после него требуется независимое обратное чтение объекта и ссылки на коммит.

Для стенда `scripts/manage_dolt_sql.py start|status|stop --foundation-root <root>` запускает только этот конфигурационный файл, проверяет точный процесс и хранит закрытые журнал и идентификатор процесса. Это локальный испытательный диспетчер, не замена производственной службе с внешним надзором.

При любом несоответствии манифеста, прав файлов, версии SQL-клиента, учётной записи, соединения, истории или обратного чтения операция закрывается ошибкой либо `unknown_outcome`. Испытания должны отдельно подтвердить SQL-запрет DDL, запрет записи в ветвь даже при SQL-гранте, перезапуск и восстановление `privileges.db`/`branch_control.db` в пустом альтернативном корне. Изменение правил ветвей может изменить режим файла; до возобновления моста оператор обязан вернуть `0600` и перепроверить права.

При откате на выпуск до 0.9.0 сначала остановите SQL-сервер и проверьте в альтернативном корне доступность старого встроенного маршрута. Не удаляйте файлы прав или журналы Dolt и не допускайте параллельных писателей. Ни наличие SQL-службы, ни подписанная поставка сами по себе не разрешают производственную активацию до G0–G8.
